THE STRATUM KERNEL (K0) #

Purpose: The STRATUM Kernel is the irreducible core of the specification—the minimum set of definitions required for K0 conformance. This section provides a self-contained reading guide for implementers who need only the essential framework without certification, concurrency, or advanced features.

NOTE

Conformance Level K0 (Kernel-Conformant): Implementers reading ONLY the Kernel sections can achieve basic STRATUM conformance. Higher conformance levels (K1: Certified-Aware, K2: Regulated-Pipeline, K3: Live-Graph) require additional sections per referenceMap("sub-sec-FKg-HIOFmN1Oiyr_KJhnT-4", "§{{sectionNumber}}.4 Structure Overview").

Kernel Components #

The Kernel consists of six essential subsystems:

Definition (1. Data Structures (referenceMap("sub-xYOy8xUJpcssgjNVmANNW", "§{{sectionNumber}}.1 Element") – referenceMap("sub-1PQdtQJCcUP4hsmjE7iJL", "§{{sectionNumber}}.2 Layer") – referenceMap("sub-przG8f9oPcQ5oNMXdlyHX", "§{{sectionNumber}}.3 Dependency"))) #

Element, Layer, Dependency — the core abstract syntax tree. Read: Definition 2.1 (Element), Definition 2.6 (Layer), Definition 2.11 (Dependency), Definition 2.8 (DEPTYPE enumeration).

Definition (2. Constraints (referenceMap("sub-CyAf_GsK2z3HhpvlCgKlD", "§{{sectionNumber}}.4 Constraint"))) #

QF_LIA + QF_LRA + QF_UF constraint language. Read: Definition 2.12 (Predicate Language), Definition 2.16 (Constraint), Theorem 2.1 (Decidability). Note: SMT-LIB 2.6 standard required for conformance.

Definition (3. Well-Formedness (referenceMap("sec-pYrht_aqaJ5gENPPS98r-", "§{{sectionNumber}}"))) #

Structural invariants that all specifications must satisfy. Read: All WF-rules including WF-ID, WF-LAYER, WF-ACYCLIC-HARD, WF-SOFT-CYCLE-BOUNDED, WF-CASCADE-TERMINATION (added v2.4.4).

Definition (4. Six Guarantees (referenceMap("sub-2rVTmZOx_FfwEKLswk1-j", "§{{sectionNumber}}.1 Traceability") – referenceMap("sub-K1-qOmCVrnDqLrLgOd_aa", "§{{sectionNumber}}.2 Completeness") – referenceMap("sub-sbASI3HUkg21rQji8CA3y", "§{{sectionNumber}}.3 Consistency") – referenceMap("sub-PNmArYZo6xNqQZsWMEHGT", "§{{sectionNumber}}.4 Groundedness") – referenceMap("sub-XWHt4rvXeJPsjryeyJk-f", "§{{sectionNumber}}.5 Determinism") – referenceMap("sub-BY56RlNT5fC29dbs7WShu", "§{{sectionNumber}}.6 Coherence"))) #

G1 (Traceability), G2 (Completeness), G3 (Consistency), G4 (Groundedness), G5 (Determinism), G6 (Coherence). These are the semantic properties that define a Valid specification. G7 (Explainability) is K1, not K0.

Definition (5. Inference Rules (referenceMap("sec-CwnDzo78GYBw57r1EI_R5", "§{{sectionNumber}}"))) #

Cascade computation (CASCADE-1, CASCADE-N, CASCADE-ATT), constraint satisfaction (CONSTR-SAT), trace computation (TRACE-ROOT, TRACE-STEP). These define the operational semantics.

Definition (6. Core Operations (referenceMap("sub-amKfbMudBf4a5EIxM14St", "§{{sectionNumber}}.1 Query Operations") – referenceMap("sub-9q6VwEYOZyqBvxep8Dw5x", "§{{sectionNumber}}.2 Modification Operations") – referenceMap("sub-doChtsVucb4PgzoofGPjB", "§{{sectionNumber}}.3 Comparison Operations"))) #

validate(S) → violations, trace(e) → path, impact(S, δ) → affected elements. These are the three required Kernel operations. Note: validateIncremental (referenceMap("sub-amKfbMudBf4a5EIxM14St", "§{{sectionNumber}}.1 Query Operations").1) is K3, not K0.

Kernel Properties #

All Kernel operations share three essential properties:

Definition (Pure) #

All Kernel functions are deterministic total functions with no side effects. No I/O, no randomness, no wall-clock time dependencies. Given the same input, always produce the same output.

Definition (Decidable) #

All Kernel judgments terminate with definite yes/no answers. No "unknown" or "timeout" results. Well-formedness checking is O(|E| + |D| + |L|²). Constraint validation is decidable via SMT solving (NP-complete, but terminates).

Definition (Compositional) #

Kernel(S₁ ⊕ S₂) = Kernel(S₁) ⊕ Kernel(S₂). Merging two specifications preserves all Kernel properties. This follows from the CRDT-based merge semantics (referenceMap("sec-FKg-HIOFmN1Oiyr_KJhnT", "§{{sectionNumber}}")) but does not require understanding CRDTs for K0 conformance.

What is NOT in the Kernel #

The following features are EXTENSIONS, not Kernel requirements:

  • Certification (referenceMap("sec-5jP_ZWlaA8SfDbhVxrG99", "§{{sectionNumber}}") – referenceMap("sec-YFHOeAjN2dYDjDiTocSSI", "§{{sectionNumber}}") – referenceMap("sec-z3nlCPJ5B1h7TUhEf25LL", "§{{sectionNumber}}") – referenceMap("sec-S3Z17-kDEc2A9A92Y0bqi", "§{{sectionNumber}}"), referenceMap("sec-ZBsFkK5bvDEL4m-rsfH17", "§{{sectionNumber}}") – referenceMap("sec-RBDT59WZE2xJyi9k5UFvY", "§{{sectionNumber}}") – referenceMap("sec-rRDDwm1LZy_CFk7nC2L0k", "§{{sectionNumber}}") – referenceMap("sec-Nei3FTlw11oOPZVBq920l", "§{{sectionNumber}}") – referenceMap("sec-x6eVbGvoVfS9GNeqNkLUG", "§{{sectionNumber}}") – referenceMap("sec-dM0e66FHuNRBmoEaMjfxF", "§{{sectionNumber}}") – referenceMap("sec-F4EMqD3954zBnfEDnmQGj", "§{{sectionNumber}}")): RTM, DO-178C/ISO 26262 mappings, STPA/FMEA. IMPORTANT

Kernel Boundary Enforcement: Some sections are explicitly marked non-Kernel. Artifact Adapters (referenceMap("sec-xEbsOCjQmAy1Uj_H6qRLr", "§{{sectionNumber}}")) introduce effectful: true to mark I/O-performing components that violate Kernel purity.
